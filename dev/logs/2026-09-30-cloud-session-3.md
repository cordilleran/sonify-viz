## Port-back (do this before the next sync)

Nothing under `tracks/mapping/` or `data/*/data-dict.yaml` is produced by a repository script (`export_mapping.py` and `build_parquet.py` write only parquet), so the vault copy is presumably the source. If the vault copy lacks these edits, the next sync of `tracks/` overwrites them.

1. Make a patch of the dictionary edits from the branch: `git diff origin/main...origin/claude/laughing-fermat-57fuql -- data/parquet/data-dict.yaml data/climate/parquet/data-dict.yaml tracks/mapping > dictionary-edits.patch`. That includes the round 2 `climate_daily` edit, and it excludes the HTML pages.
2. In the vault's project folder, where these files sit at the same relative paths, check with `patch -p1 --dry-run < dictionary-edits.patch`, then apply it without `--dry-run`. If the vault's copies have drifted, the dry run will say which hunks fail; apply those by hand.
3. Regenerate the HTML pages from the vault copies, not from the patch: `data-dict render <dictionary> -o dictionary/<name>.html`, with `uvx --from data-dict-yaml==0.0.3`. The output is deterministic, so a clean sync should reproduce exactly the pages on the branch. The page names are `water-year-records`, `climate-pair-records`, and `<track>-mapping`.
4. Copy `dev/dictionary/dd_lint.py` into the vault's scripts (or run it from `dev/`) and add it to the preflight. Run it after every sync: `python dev/dictionary/dd_lint.py` exits 1 and lists problems if the old dictionaries return.
5. If the sync script has a whitelist, adding `data/*/data-dict.yaml` is not needed: `data/` is not among the folders `WORKFLOW.md` says the sync overwrites. `tracks/` is, so steps 1 and 2 matter most for `tracks/mapping/`.
